# Proposed I7 allocation-epoch boundary

**Decision requested:** permit a completed collection boundary as an explicit host premise in the I7 physical-memory proof, subject to the ownership and admission gates below. Recommend this over assuming an unproved collector-progress bound. This is a proposed amendment, not an admitted runtime, completed proof or implementation authorization. Full stage 1 remains open.

This design answers request242710db under full request42c2ce37. It uses Tailapp main `b583cdc4c3bcb1f6359f3298c067ae2298b02ca7`, private evaluator `bebeed31322f96ce9d75044acd71382466fde5c2`, private source-snapshot helper `c9c774d295a24ef3ca30504dcc444fc4ecc01495`, and Go1.26.7. The [governing contract](notes/2026-09-05-capability-context-contract.md@b583cdc4c3bcb1f6359f3298c067ae2298b02ca7:798) requires physical bounds as well as logical charges. The signed feasibility finding under e9c3c1b1 records the missing implication. Neither its source hashes nor the successful500-evaluation fixture prove a runaway or its impossibility.

## Choice and exact changed premises

| | Existing obligation | Proposed additional premise |
|---|---|---|
| Repeated events | Each event owns cumulative W/A/D; freeing storage refunds nothing. Background GC supplies no proved allocation-count deadline. | Fresh bounded allocation epochs pass through one process-wide ownership boundary; the next epoch waits for release and completed collection. |
| Caller concurrency | The fixture serializes its own budget. That does not constrain arbitrary hosts or different engines. | An admitted host supplies a bounded dispatcher and queue, with every relevant loader/evaluator path in the same domain. Concurrency remains a host API capability; owned allocation epochs are serialized initially. No unbounded goroutine or payload queue may accumulate while waiting. |
| Other host work | Trusted code remains subject to the physical proof; being outside the evaluator is not zero cost. | Every other allocator in the process either joins the domain or has an independent bound on its still-allocated storage, including garbage, during an arbitrarily long epoch/collection wait. A bound on reachable data alone is insufficient. |
| Retention | Per-event allowance does not bound the number of compiled applications, outputs, snapshots or caches retained by a host. | Each admitted host declares and proves finite cross-epoch populations and per-member sizes. Reload includes simultaneous old/new state. Results leave an epoch only into a reserved bounded ownership slot. |

The original option remains legitimate: prove a bound on allocation before a completed mark/sweep under the existing host assumptions, including limiter-enabled assists, non-preemptible allocation and scheduling. No such proof or selected-workload limiter counterexample has been established. The proposed boundary replaces that progress obligation with an explicit ordering obligation. It does not make other host storage disappear. A fixed-capacity implementation could avoid GC, but replacing the existing Go parser, strings, regex and codecs would be a larger change.

**Public contract change requiring adoption:** the reusable jsonataddl module remains usable by external consumers, but its proposed I7-admitted interface permits only one allocation domain per process, shared across all engines and consumers, with serialized owned epochs. Two independently replenished allowance domains in one process would no longer satisfy that interface. This is a real narrowing of the reusable module contract; the serial fixture does not authorize it. Tailapp, Gitseq and external consumers each need host admission under these premises. The assigned four targets remain Darwin/Linux on ARM64/AMD64 with pinned Go1.26.7; this proposal neither changes the adopted build/environment profile nor proves that an actual host meets it.

## Ownership boundary and source changes it would require

Use a trusted host coordinator with an opaque, generation-bound epoch lease. The proposed API has coordinator acquisition of a bounded preparation/event epoch, epoch-bound preparation and one-use event sessions, and evaluation into a pre-reserved result slot. These are required capabilities, not finalized Go signatures. No preparation/session entry manufactures its own fresh lease. The coordinator owns its lifetime, admission state and collector call. A copied lease handle cannot renew the generation or create concurrent ownership; every entry validates the same live domain/generation and session-use state. Nested epoch acquisition refuses rather than deadlocking. The core implements the fixed collector-backed domain object; the host places it outside its orchestration critical sections. Admission verifies the process ownership stated above. A caller-supplied boolean or callback that merely claims collection finished is insufficient. This is source-reviewed trusted integration, not protection against arbitrary Go code in the same process.

The boundary has four states: **idle → active → releasing → collecting → idle**. Only idle admits another epoch. Acquire before constructing the epoch's source maps, decoded inputs, metadata or result buffers. One event epoch includes its normalizer and all emitted folds under the same event counters. Loading/reloading is a separately bounded preparation epoch; splitting it from evaluation never replenishes an event's allowance. Refusal, panic recovery and cancellation still pass through release/collection after any owned allocation. A request cancelled before admission creates no owned epoch. Collection itself is not made cancellable: cancellation cannot reopen admission while a collector is still running. Host cancellation/backpressure remains a transient retry outcome, not a deterministic resource failure or projection gap.

The current `EvaluationResult` in `jsonataddl/evaluate.go:41-46` exposes ordinary maps and slices; its type does not enforce cross-epoch ownership. The proposed admitted API instead requires a domain-owned bounded result-slot reservation before evaluation and returns an opaque handle tied to that slot/generation. Reading or copying a result requires a live epoch and reserved destination capacity; raw backing maps/slices cannot be exported from the admitted API. Release invalidates transient handles; only explicitly transferred reserved slots remain valid. The caller still must not copy or retain unaccounted data through arbitrary Go code: its reviewed integration and storage census discharge that premise. Existing unleased entry points cannot count as I7-admitted paths. This is part of the `core.interface` change, not only an acceptance-test aspiration.

Release closes rows and source handles, commits or rolls back the transaction, releases authorizer seats and application locks, transfers only reserved retained results, and returns from the helper whose stack held transient roots. Then collect from an ordinary preemptible goroutine frame. `runtime/mgc.go:738-743` lets gcStart return without starting a cycle on g0, while runtime locks are held, or with preemption disabled; prove this calling condition in the coordinator. Do not rely only on assigning nil inside a live helper or on an undocumented finalizer. No domain lock needed by another host operation or cleanup may be held across a blocking admission/collection wait. After collection, reacquire and revalidate mutable revision/frontier state before beginning the next epoch. Existing per-record order and atomic normalizer/fold/frontier transaction stay intact.

The proposed coordinator crosses those two responsibilities explicitly. It does not add a wire authority, provider privilege or SQLite extension.

## Does runtime.GC suffice?

**It supplies a completed-cycle fact, not the whole occupancy theorem.** Go1.26.7 `runtime/mgc.go:522-591` waits for current marking and ensures a following full cycle. The sweep loops at :564 and :579 may exit because a later cycle began, not only because their own sweep finished. This is safe for the completed-cycle claim because gcStart finishes the previous sweep under stop-the-world at :868-871 before the next concurrent scan. It does not mean the collector is idle when GC returns. Objects allocated by other actors after the chosen completed sweep are charged separately by their independent still-allocated-storage bound; without that premise the post-sweep induction does not follow.

The attached four-target source-selection evidence verifies that cross-target `go list` selects these same seven hashed runtime/sync/size-class files from one pinned Go1.26.7 toolchain for all four targets. It does not compare four separately distributed toolchains, execute the three non-native targets, or prove complete platform call graphs or host admission. No fixed collection-completion time is proved. `runtime/proc.go:6476` specifies the two-minute periodic force-GC trigger, not a maximum GC latency or an allocation bound. If collection stalls, no new domain epoch may allocate; latency suffers while memory safety remains conditional on bounded other actors.

All four builds still need the complete reviewed source/call graph and platform runtime allowances. CGO/debug/foreign entry exclusions must be established for the actual host, not inferred from fixture binaries. Application finalizers/cleanups must not retain or resurrect unbounded epoch data or allocate outside the domain; runtime/stdlib cleanups need a separate bounded audit. `runtime.GC` does not wait for every finalizer or cleanup to finish. One collection also leaves a `sync.Pool` victim generation: `sync/pool.go:257-281` drops old victims and moves primary pools to victims. Keep an independently bounded pool-population/previous-epoch term instead of treating all pools as empty. I considered the reviewer's simplification: two collections with no intervening pool use clear both generations. It would remove the victim term only after proving process-wide pool quiescence, including other permitted bounded actors and cleanup paths. That is a stronger host restriction and a second collection; this minimal proposal retains one collection and the explicit pool obligation. If that obligation cannot be proved, the gate fails; a proved quiescent two-collection alternative would require its own explicit premise, not a silent substitution. Finalizers that participate in unbounded resurrection fail this profile; a claimed explicit Close does not prove their absence.

## Occupancy induction without the span-count cycle

Use 8192-byte pages and a largest small-class span of 10 pages, from `internal/runtime/gc/sizeclasses.go:91-93` (`PageShift=13`, `MaxSizeClassNPages=10`), now recorded in the manifest. First bound objects/bytes directly from the owned live roots and precharged cumulative allocation inventory. Do **not** begin with a span population already derived from Qmax.

At a completed-sweep cut, charge every ordinary nonempty small-object span to one object it contains. If GC returned in a later active cycle, use the earlier completed cut plus the bounded intervening allocation described above, rather than pretending the current heap has just been swept. If `s` is the largest supported small-class span in pages and `L` bounds the number of retained small objects, these spans cost at most `s*L` pages. Charge each retained large object its own rounded page extent. Separately count bounded empty cached/in-flight spans, unused P-page caches, manual stack/runtime spans and startup padding. Pool victims and bounded concurrent runtime objects are included in those direct root/object populations. Validate the span witness and cache cases against the exact allocator; they are proof obligations, not assumed equalities.

During the next epoch, add the full rounded extent of every new allocation from its cumulative bound, even if it dies immediately or moves during a copying growth. Include bounded runtime/host allocations and retained old/new reload overlap. At the next release/collection, the owned transient roots disappear and the post-sweep bound applies again. Thus the proposed induction has the form

`Qmax ≤ Qretained + Qpool + Qepoch + Qruntime + Qcache/manual/padding`.

Every right-hand term must be independently finite in admitted source/host parameters, without lifetime event count, Qmax or a span count derived from Qmax. If runtime allocation depends on the span population, discharge that particular term through an independent object/path bound or solve an explicit non-circular inequality; do not substitute the earlier span lemma back into Qmax. Only after this step may the existing span-descriptor, GC-bit and heap-growth-history lemmas consume Qmax. The final physical F still includes persistent profile/allocator metadata, retained mappings and other non-page-heap storage. This document does not fill in the missing numerical terms.

## Semantics, identity and cost

W/A/D charges and their deterministic failure selection do not change. No GC refunds, samples, goals or timing values enter semantic decisions. Complete precharging and cumulative per-event W/A/D bound adversary-controlled evaluator work, allocations and depth, including refusal paths. Preparation needs its own finite charges and source limits. These controls prevent an input from purchasing unlimited metered work, but do not establish a wall-clock deadline for collector, scheduler, filesystem/SQLite blocking or other host activity. Process-wide serialization therefore adds an availability coupling; bounded dispatch, host I/O cancellation/deadlines and lock/cleanup admission must address it explicitly, without claiming a denial-of-service impossibility theorem. Language, aliases/partials, provider admission and verified-context boundaries remain as adopted. Collection delays and cancellation are operational, and must not be persisted as deterministic resource gaps. Process death before commit leaves the transaction recoverable; death after commit but before queue acknowledgement must retain the existing replay/already-applied handling.

The lease/API requirement changes `core.interface`; actual host scheduling changes `host.orchestration` from its then-current version. The adopted I7 `core.jsonata` version must identify the actual admitted evaluator/profile; a new physical-profile meaning cannot silently reuse an identity. Keep the adopted ten-component shape, including extension identity, and change other component values only for corresponding changes. Main currently has nine components; that is not the adopted I7 shape. Changing `host.orchestration` from main's `two-stage-txn/3` changes CurrentRuntimeID and makes existing projections upgrade-pending (`internal/profile/runtime.go:18-23,34`). Stage 2 must exercise the forced acknowledged upgrade-or-reset path, including the empty registry, before activation/continuation; no silent resume under the old identity is allowed. This proposal chooses no final version string or runtime digest.

Per-epoch collection may impose substantial global pauses, block unrelated work and reduce throughput. No latency measurement is claimed. Bounded queue/backpressure and cancellation behavior need explicit host acceptance. A timeout cannot serve as permission to skip collection. Deadlock freedom requires a concrete lock/cleanup census; the abstract state machine alone does not prove it.

## Stage allocation and adoption text

**Stage 1:** prove the complete four-build component theorem under explicitly enumerated host premises; implement reviewed core ownership/lease and bounded acquisition/session interfaces only after adoption and within the existing assignment. An orchestration fixture must exercise concurrent attempted entries, retained ownership, rejection and cancellation; a serial loop alone cannot certify a host. Do not declare full I7 complete from a conditional outline, move its physical-proof gate to release, or publish a dependency before its existing gates.

**Minimum separate stage-2 assignment after adoption:** integrate the coordinator into the real Tailapp acquisition/reload/event paths, with bounded dispatch and cross-epoch ownership, a census of other host allocation, lock-safe collection, identity/activation changes and process-death recovery. Preserve existing data-plane ordering and the single event transaction. Other hosts require their own bounded assignments; this child assigns none of them. Stage1 cannot certify production host admission, and stage2 cannot dispense with the completed component proof.

Acceptance must observe real orchestration: a second fresh epoch cannot enter while the collector is held; all allocating rejection/cancellation/reload paths close ownership; no transaction/authorizer/application lock remains held at collection; results cannot escape reserved slots; a different engine/core entry point cannot bypass the coordinator; concurrent waiting payload/G populations stay bounded. Remove each boundary/ownership check and require the corresponding test to fail. Collector fakes prove ordering only; the pinned-runtime proof establishes collection. Check the collector's ordinary preemptible-frame requirement, all four builds, forced projection upgrade-or-reset on host.orchestration change, deadlock/cancellation and crash recovery. Measurements supplement these obligations and never replace them.
