# Proposed I7 allocation-epoch boundary

**Decision requested:** permit a completed collection boundary as an explicit host premise in the I7 physical-memory proof, subject to the ownership and admission gates below. Recommend this over assuming an unproved collector-progress bound. This is a proposed amendment, not an admitted runtime, completed proof or implementation authorization. Full stage 1 remains open.

It uses Tailapp main `b583cdc4c3bcb1f6359f3298c067ae2298b02ca7`, private evaluator `bebeed31322f96ce9d75044acd71382466fde5c2`, private source-snapshot helper `c9c774d295a24ef3ca30504dcc444fc4ecc01495`, and Go1.26.7. The [governing contract](notes/2026-09-05-capability-context-contract.md@b583cdc4c3bcb1f6359f3298c067ae2298b02ca7:798) requires physical bounds as well as logical charges. The signed feasibility finding under e9c3c1b1 records the missing implication. Neither its source hashes nor the successful500-evaluation fixture prove a runaway or its impossibility.

## Choice and exact changed premises

| | Existing obligation | Proposed additional premise |
|---|---|---|
| Repeated events | Each event owns cumulative W/A/D; freeing storage refunds nothing. Background GC supplies no proved allocation-count deadline. | Fresh bounded allocation epochs pass through one process-wide ownership boundary; the next epoch waits for release and completed collection. |
| Caller concurrency | The fixture serializes its own budget. That does not constrain arbitrary hosts or different engines. | An admitted host supplies a bounded dispatcher and queue, with every relevant loader/evaluator path in the same domain. Concurrency remains a host API capability; owned allocation epochs are serialized initially. No unbounded goroutine or payload queue may accumulate while waiting. |
| Other host work | Trusted code remains subject to the physical proof; being outside the evaluator is not zero cost. | Every other allocator in the process either joins the domain or has an independent bound on its still-allocated storage, including garbage, during an arbitrarily long epoch/collection wait. A bound on reachable data alone is insufficient. |
| Retention | Per-event allowance does not bound the number of compiled applications, outputs, snapshots or caches retained by a host. | Each admitted host declares and proves finite cross-epoch populations and per-member sizes. Reload includes simultaneous old/new state. Results leave an epoch only into a reserved bounded ownership slot. |

The original option remains legitimate: prove a bound on allocation before a completed mark/sweep under the existing host assumptions, including limiter-enabled assists, non-preemptible allocation and scheduling. No such proof or selected-workload limiter counterexample has been established. The proposed boundary replaces that progress obligation with an explicit ordering obligation. It does not make other host storage disappear. A fixed-capacity implementation could avoid GC, but replacing the existing Go parser, strings, regex and codecs would be a larger change.

**No silent host restriction:** the serial fixture is not an admission profile. Tailapp, Gitseq and library hosts must each be assessed against the changed premises. A host that cannot meet them has no I7 admission from this proposal; accepting that changed obligation requires the separate adoption. The four supported targets remain Darwin/Linux on ARM64/AMD64 with pinned Go1.26.7 and the reviewed build/environment profile. No new numerical operating limit is selected here.

## Ownership boundary and source changes it would require

Use a trusted host coordinator with an opaque, generation-bound epoch lease. The new admitted core APIs require the live lease for acquisition/preparation and event sessions; they cannot manufacture a fresh one. The coordinator owns its lifetime, admission state and collector call. A copied lease handle cannot renew the generation or create concurrent ownership; every entry validates the same live domain/generation and session-use state. Nested epoch acquisition refuses rather than deadlocking. The core implements the fixed collector-backed domain object, while the host chooses the outer orchestration boundary and owns its one admitted process instance; another engine cannot create an independent allowance domain. A caller-supplied boolean or callback that merely claims collection finished is insufficient. This is source-reviewed trusted integration, not protection against arbitrary Go code in the same process.

The boundary has four states: **idle → active → releasing → collecting → idle**. Only idle admits another epoch. Acquire before constructing the epoch's source maps, decoded inputs, metadata or result buffers. One event epoch includes its normalizer and all emitted folds under the same event counters. Loading/reloading is a separately bounded preparation epoch; splitting it from evaluation never replenishes an event's allowance. Refusal, panic recovery and cancellation still pass through release/collection after any owned allocation. A request cancelled before admission creates no owned epoch. Collection itself is not made cancellable: cancellation cannot reopen admission while a collector is still running. Host cancellation/backpressure remains a transient retry outcome, not a deterministic resource failure or projection gap.

Release closes rows and source handles, commits or rolls back the transaction, releases authorizer seats and application locks, transfers only reserved retained results, and returns from the helper whose stack held transient roots. Then collect from an ordinary preemptible frame. Do not rely only on assigning nil inside a live helper or on an undocumented finalizer. No domain lock needed by another host operation or cleanup may be held across a blocking admission/collection wait. After collection, reacquire and revalidate mutable revision/frontier state before beginning the next epoch. Existing per-record order and atomic normalizer/fold/frontier transaction stay intact.

The reusable-core/host separation follows [the architecture note](notes/2026-08-28-tailapp-architecture.md@b583cdc4c3bcb1f6359f3298c067ae2298b02ca7:101): core owns semantic validation and metered operations; host owns source acquisition, connections, transactions, scheduling and lifecycle. The proposed coordinator crosses those two responsibilities explicitly. It does not add a wire authority, provider privilege or SQLite extension.

## Does runtime.GC suffice?

**It supplies the collection fact, not the whole occupancy theorem.** The common Go1.26.7 `runtime/mgc.go:522-591` waits for the current marking cycle, ensures a following full cycle, and completes or waits for its sweep. This source contract applies to all four targets. It does not require a fixed completion time. If collection stalls, no new domain epoch may allocate; latency and availability suffer while the memory induction remains conditional on other actors staying bounded.

All four builds still need the complete reviewed source/call graph and platform runtime allowances. CGO/debug/foreign entry exclusions must be established for the actual host, not inferred from fixture binaries. Application finalizers/cleanups must not retain or resurrect unbounded epoch data or allocate outside the domain; runtime/stdlib cleanups need a separate bounded audit. `runtime.GC` does not wait for every finalizer or cleanup to finish. One collection also leaves a `sync.Pool` victim generation: `sync/pool.go:257-281` drops old victims and moves primary pools to victims. Count bounded pool populations, or the bounded previous-epoch contribution, rather than treating all pools as empty. Finalizers that participate in unbounded resurrection fail this profile; a claimed explicit Close does not prove their absence.

## Occupancy induction without the span-count cycle

Use page units of8192 bytes. First bound objects/bytes directly from the owned live roots and precharged cumulative allocation inventory. Do **not** begin with a span population already derived from Qmax.

After a completed sweep, charge every ordinary nonempty small-object span to one object it contains. If `s` is the largest supported small-class span in pages and `L` bounds the number of retained small objects, these spans cost at most `s*L` pages. Charge each retained large object its own rounded page extent. Separately count bounded empty cached/in-flight spans, unused P-page caches, manual stack/runtime spans and startup padding. Pool victims and bounded concurrent runtime objects are included in those direct root/object populations. Validate the span witness and cache cases against the exact allocator; they are proof obligations, not assumed equalities.

During the next epoch, add the full rounded extent of every new allocation from its cumulative bound, even if it dies immediately or moves during a copying growth. Include bounded runtime/host allocations and retained old/new reload overlap. At the next release/collection, the owned transient roots disappear and the post-sweep bound applies again. Thus the proposed induction has the form

`Qmax ≤ Qretained + Qpool + Qepoch + Qruntime + Qcache/manual/padding`.

Every right-hand term must be independently finite in admitted source/host parameters, without lifetime event count, Qmax or a span count derived from Qmax. If runtime allocation depends on the span population, discharge that particular term through an independent object/path bound or solve an explicit non-circular inequality; do not substitute the earlier span lemma back into Qmax. Only after this step may the existing span-descriptor, GC-bit and heap-growth-history lemmas consume Qmax. The final physical F still includes persistent profile/allocator metadata, retained mappings and other non-page-heap storage. This document does not fill in the missing numerical terms.

## Semantics, identity and cost

W/A/D charges and their deterministic failure selection do not change. No GC refunds, samples, goals or timing values enter semantic decisions. Language, aliases/partials, provider admission and verified-context boundaries remain as adopted. Collection delays and cancellation are operational, and must not be persisted as deterministic resource gaps. Process death before commit leaves the transaction recoverable; death after commit but before queue acknowledgement must retain the existing replay/already-applied handling.

The lease/API requirement changes `core.interface`; actual host scheduling changes `host.orchestration` from its then-current version. The adopted I7 `core.jsonata` version must identify the actual admitted evaluator/profile; a new physical-profile meaning cannot silently reuse an identity. Keep the adopted ten-component shape, including extension identity, and change other component values only for corresponding changes. Main currently has nine components; that is not the adopted I7 shape. Stored-runtime activation/continuation guards and acknowledged reset remain mandatory even for an empty registry. This proposal chooses no final version string or runtime digest.

Per-epoch collection may impose substantial global pauses, block unrelated work and reduce throughput. No latency measurement is claimed. Bounded queue/backpressure and cancellation behavior need explicit host acceptance. A timeout cannot serve as permission to skip collection. Deadlock freedom requires a concrete lock/cleanup census; the abstract state machine alone does not prove it.

## Stage allocation and adoption text

**Stage 1:** prove the complete four-build component theorem under explicitly enumerated host premises; implement reviewed core ownership/lease and bounded acquisition/session interfaces only after adoption and within the existing assignment. An orchestration fixture must exercise concurrent attempted entries, retained ownership, rejection and cancellation; a serial loop alone cannot certify a host. Do not declare full I7 complete from a conditional outline, move its physical-proof gate to release, or publish a dependency before its existing gates.

**Minimum separate stage-2 assignment after adoption:** integrate the coordinator into the real Tailapp acquisition/reload/event paths, with bounded dispatch and cross-epoch ownership, a census of other host allocation, lock-safe collection, identity/activation changes and process-death recovery. Preserve existing data-plane ordering and the single event transaction. Other hosts require their own bounded assignments; this child assigns none of them. Stage1 cannot certify production host admission, and stage2 cannot dispense with the completed component proof.

Acceptance must observe real orchestration: a second fresh epoch cannot enter while the collector is held; all allocating rejection/cancellation/reload paths close ownership; no transaction/authorizer/application lock remains held at collection; results cannot escape reserved slots; a different engine/core entry point cannot bypass the coordinator; concurrent waiting payload/G populations stay bounded. Remove each boundary/ownership check and require the corresponding test to fail. Collector fakes prove ordering only; the pinned-runtime proof establishes collection. Check all four builds, exact identity/reset behavior, deadlock/cancellation and crash recovery. Measurements supplement these obligations and never replace them.

**Proposed adoption wording:** “Permit a host-owned completed collection between bounded allocation epochs as an explicit I7 physical-proof premise, with the ownership, concurrency, retention and other-host-allocation obligations in this exact reviewed design. Preserve the full four-build physical-proof and admission gates, logical semantics and stage split. This decision authorizes the corresponding stage-1 design correction; actual host integration and any public publication require their existing separate assignments and acceptance. No existing host is deemed admitted by this decision.”

Remaining unknowns are the numerical independent Q terms, complete final-host/runtime/cleanup census, precise coordinator API and lock ordering, bounded dispatch/retention parameters and operational latency. These remain acceptance gates. Independent design approval and Hugh's ratification of this child accept the design work; adoption of the quoted premise is a separate explicit act.
